# 🧟‍♂️ Grader 서비스 등급 판정 로직 설계 (SCRUM-98)

## 📌 개요
이 문서는 GitHub PR(Pull Request) 방치 기간에 따라 페널티 등급(Zombie Grade)을 부여하는 **Grader 서비스**의 핵심 비즈니스 로직을 정의합니다.

## 🎯 상태값 (ZombieGrade Enum)
수연 님이 세팅한 `SCRUM-27` Enum 값을 기준으로 합니다.
- `SPROUT` (새싹좀비)
- `ZOMBIE` (좀비)
- `BOSS` (보스좀비)

---

## 🧪 TDD 기반 비즈니스 로직 (Given-When-Then)

### 1. 기본 판정 로직
- **[Given]** PR 방치 기간이 3일 미만일 때 (예: 2일 23시간)
  - **[When]** 자정 스케줄러가 판정을 실행하면
  - **[Then]** 아무 등급도 부여하지 않는다 (등급 없음).

- **[Given]** PR 방치 기간이 정확히 3일 이상 ~ 7일 미만일 때
  - **[When]** 자정 스케줄러가 판정을 실행하면
  - **[Then]** `SPROUT` (새싹좀비) 등급을 부여한다.

- **[Given]** PR 방치 기간이 정확히 7일 이상 ~ 14일 미만일 때
  - **[When]** 자정 스케줄러가 판정을 실행하면
  - **[Then]** `ZOMBIE` (좀비) 등급으로 승격한다.

- **[Given]** PR 방치 기간이 정확히 14일 이상일 때
  - **[When]** 자정 스케줄러가 판정을 실행하면
  - **[Then]** `BOSS` (보스좀비) 등급으로 승격하고, 전체 알림(Notifier) 시스템 호출 이벤트를 발행한다.

### 2. 예외 처리 로직 (Edge Cases)
- **[Given]** 이미 `BOSS` 등급인 PR이 있을 때
  - **[When]** 판정 로직이 실행되면
  - **[Then]** 중복해서 승격하지 않고 기존 상태를 유지한다.

- **[Given]** 이미 병합(Merged)되거나 닫힌(Closed) PR일 때
  - **[When]** 판정 로직이 실행되면
  - **[Then]** 판정 대상에서 완전히 제외한다.

## ⚙️ 기술적 고려사항
- **Virtual Threads (가상 스레드):** 대량의 PR 목록(예: 100개 이상)을 자정에 동시 다발적으로 처리하기 위해 Java 17의 가상 스레드를 도입하여 병렬 처리 성능을 극대화한다.
