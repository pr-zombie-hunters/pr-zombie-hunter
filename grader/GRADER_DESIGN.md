# 🧟‍♂️ Grader 서비스 등급 판정 로직 설계 (SCRUM-98)

## 📌 개요
이 문서는 GitHub PR(Pull Request) 방치 기간에 따라 페널티 등급(Zombie Grade)을 부여하는 **Grader 서비스**의 핵심 비즈니스 로직을 정의합니다.

## 🎯 상태값 (ZombieGrade Enum)
수연 님이 세팅한 `init-core-setup` 브랜치의 Enum 값을 기준으로 합니다.
- `SEEDLING` (새싹좀비)
- `ZOMBIE` (좀비)
- `BOSS` (보스좀비)

---

## 🧪 TDD 및 BDD 기반 비즈니스 로직 (Given-When-Then)

### 1. 기본 판정 로직
- **[SCRUM-72] 3일 미만 경계값 검증**
  - **[Given]** PR 방치 기간이 3일 미만일 때
  - **[When]** 등급 판정을 실행하면
  - **[Then]** 아무 등급도 부여하지 않는다 (등급 없음).

- **[SCRUM-101] 새싹좀비(SEEDLING) 부여**
  - **[Given]** PR 방치 기간이 정확히 3일 이상 ~ 7일 미만일 때
  - **[When]** 등급 판정을 실행하면
  - **[Then]** `SEEDLING` (새싹좀비) 등급을 부여한다.

- **[SCRUM-102] 좀비(ZOMBIE) 승격**
  - **[Given]** PR 방치 기간이 정확히 7일 이상 ~ 14일 미만일 때
  - **[When]** 등급 판정을 실행하면
  - **[Then]** `ZOMBIE` (좀비) 등급으로 승격한다.

- **[SCRUM-73] 보스좀비(BOSS) 승격 및 전체 알림**
  - **[Given]** PR 방치 기간이 14일 이상일 때
  - **[When]** 등급 판정을 실행하면
  - **[Then]** `BOSS` (보스좀비) 등급으로 승격하고, 전체 알림 이벤트를 호출한다.

### 2. 예외 및 중복 방지 로직
- **[SCRUM-103] 보스좀비 중복 승격 방지**
  - **[Given]** 이미 등급이 `BOSS` (보스좀비)인 PR일 때
  - **[When]** 등급 판정을 재실행하면
  - **[Then]** 중복 승격 및 알림을 방지하기 위해 등급 변화 없이 그대로 유지한다.

- **[SCRUM-104] 머지(Merge)된 PR 판정 제외**
  - **[Given]** 이미 Merge(병합)가 완료된 PR일 때
  - **[When]** 등급 판정을 실행하면
  - **[Then]** 판정 대상에서 완전히 제외한다.

### 3. 인프라 요구사항 (가상 스레드)
- **[SCRUM-105] 대용량 PR 동시 판정**
  - **[Given]** 판정해야 할 PR 목록이 100개일 때
  - **[When]** 자정 스케줄러가 판정을 실행하면
  - **[Then]** 가상 스레드(Virtual Thread)를 활용하여 100개를 전체 동시 처리하며, 순서는 보장하지 않아도 무방하다.
